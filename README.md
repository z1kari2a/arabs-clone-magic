# نظام ERP — إدارة المشتريات واحتساب التكلفة النهائية

نظام عربي متكامل (RTL) لإدارة أوامر الشراء والاستيراد، يوزّع مصاريف الشحن
والجمارك على الأصناف، ويحتسب **التكلفة النهائية للكرتون (Landed Cost)**،
ثم يقترح **سعر البيع لكل وجهة**.

**🌐 الموقع المباشر:** <https://fikradigital.online>

## 1. ما الذي يفعله النظام

| البند               | التفصيل                                                                                                    |
| ------------------- | ---------------------------------------------------------------------------------------------------------- |
| **الغرض**           | تسجيل أوامر الشراء ← توزيع المصاريف على الأصناف ← احتساب تكلفة الكرتون ← اقتراح سعر البيع                  |
| **الواجهة**         | عربية بالكامل (RTL) بنمط ERP كلاسيكي: شريط أوامر + جداول قابلة للتحرير + اختصارات لوحة مفاتيح              |
| **مكان البيانات**   | متصفح الجهاز (localStorage) في نسخة الويب · ملف SQLite محلي في نسخة سطح المكتب · نسخ احتياطي سحابي اختياري |
| **العملة المرجعية** | الدولار الأمريكي (USD) — كل التكاليف تُحتسب به مهما كانت عملة الفاتورة                                     |
| **يعمل بلا إنترنت** | نعم في نسخة سطح المكتب (الخطوط مضمَّنة، لا طلبات شبكة عند الإقلاع)                                         |
| **التقنيات**        | TanStack Start · React 19 · TypeScript · Tailwind 4 · Nitro · Electron · SQLite · Supabase                 |

### أبرز المزايا

- **توزيع مصاريف بثلاث طرق:** حسب CBM (الحجم) · حسب القيمة (مئوي) · متوسط الاثنتين — والمجموع يعود مطابقاً للمصاريف الفعلية دائماً.
- **تثبيت أسعار الصرف على المستند** لحظة الحفظ، فتعديل جدول العملات لاحقاً لا يمسّ الفواتير القديمة.
- **تسعير متعدد الوجهات:** لكل وجهة نسبة مصاريف إضافية ونسبة ربح مستقلة.
- **استيراد وتصدير Excel** بنفس مسميات الأعمدة المعتمدة، ويقبل الأرقام العربية `٠١٢٣` والفاصلة `,`.
- **سجل تدقيق كامل:** كل إضافة/تعديل/حذف مع المستخدم والوقت والقيمة قبل وبعد.
- **صلاحيات مطبّقة على الأزرار وعلى الاختصارات معاً** (مدير / مستخدم / مطالع).

## 3. التثبيت والتشغيل

### الخطوة 1 — استنساخ المشروع

```bash
git clone https://github.com/z1kari2a/arabs-clone-magic.git
cd arabs-clone-magic
```

### الخطوة 2 — تثبيت الحزم

```bash
npm install
```

### الخطوة 3 — إعداد متغيّرات البيئة

```bash
cp .env.example .env
# ثم افتح .env واملأ القيم (اشرح تفصيلاً في القسم 4)
```

### الخطوة 4 — التشغيل

```bash
npm run dev
```

افتح العنوان الظاهر في الطرفية (عادةً <http://localhost:8080>).
أي تعديل على الكود ينعكس فوراً بلا إعادة تشغيل.

### بناء نسخة الإنتاج وتشغيلها

```bash
npm run build                          # يُنتج مجلد .output
PORT=8080 node .output/server/index.mjs
```

أو للمعاينة السريعة بعد البناء:

```bash
npm run preview
```

## 4. متغيّرات البيئة (.env)

انسخ `.env.example` إلى `.env` واملأ القيم من لوحة تحكم مشروعك على
[Supabase](https://supabase.com) ← **Project Settings → API**:

```bash
SUPABASE_PROJECT_ID="معرّف-المشروع"
SUPABASE_PUBLISHABLE_KEY="المفتاح-العام"
SUPABASE_URL="https://xxxx.supabase.co"

VITE_SUPABASE_PROJECT_ID="نفس-معرّف-المشروع"
VITE_SUPABASE_PUBLISHABLE_KEY="نفس-المفتاح-العام"
VITE_SUPABASE_URL="نفس-الرابط"
```

| المتغيّر                    | الدور                                                                                                                              |
| --------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| `SUPABASE_*`                | تُقرأ في الخادم (Nitro / API routes)                                                                                               |
| `VITE_SUPABASE_*`           | تُحقن في حزمة المتصفح — ولذلك **يجب أن تكون المفاتيح العامة (publishable) فقط**                                                    |
| `SUPABASE_SERVICE_ROLE_KEY` | اختياري، **للخادم حصراً** (النسخ الاحتياطي السحابي وخدمات الترخيص). لا تضعه في أي متغيّر يبدأ بـ `VITE_` ولا ترفعه إلى مستودع عام. |

> Supabase مستخدَم للنسخ الاحتياطي السحابي وخدمات الترخيص فقط. النظام يعمل
> محلياً بدونه، لكن ميزتَي النسخ السحابي والترخيص تتعطّلان.

## 5. التسجيل وأول دخول

![شاشة الدخول](docs/screenshots/01-login.png)

### إنشاء حساب المدير (أول مرة فقط)

عند أول فتح للنظام لا يوجد أي مستخدم:

1. افتح النظام فيظهر لك نموذج **الدخول / التسجيل**.
2. اضغط **تسجيل جديد** واملأ الاسم والبريد وكلمة المرور.
3. **أول حساب يُنشأ يصبح «مدير» تلقائياً** — بصلاحيات كاملة وبلا انتظار موافقة.

### تسجيل المستخدمين اللاحقين

| الحالة             | ما يحدث                                                                                |
| ------------------ | -------------------------------------------------------------------------------------- |
| مستخدم يسجّل بنفسه | يبقى **«قيد المراجعة»** ولا يستطيع الدخول حتى يوافق عليه المدير من شاشة **المستخدمون** |
| المدير ينشئ الحساب | الحساب **نشط فوراً**، والمدير يحدّد دوره (مدير / مستخدم / مطالع)                       |

![المستخدمون](docs/screenshots/10-users.png)

من شاشة **المستخدمون** يستطيع المدير: الموافقة على التسجيلات المعلّقة، تغيير الأدوار،
وتفعيل أو تعطيل الحسابات.

## 6. التفعيل والترخيص

نسخة **الويب** على fikradigital.online تعمل بلا ترخيص.
نسخة **سطح المكتب المحمية** تطلب **رمز ترخيص** عند أول تشغيل، ثم:

1. تفعّل الرمز على خادم التراخيص وتربطه بمعرّف الجهاز.
2. تنزّل حزمة التطبيق المشفّرة وتشغّلها.
3. ترسل نبضة (heartbeat) كل 30 دقيقة — إن أُلغي الترخيص يتوقف التطبيق.

**إدارة التراخيص** من `/admin/licenses` (للمدير فقط): إنشاء رمز، تحديد النوع
(شهري / دائم)، ومتابعة الأجهزة المفعّلة وإلغاء تفعيلها.

> ⚠️ **النسخ الاحتياطي السحابي يتطلب ترخيصاً مفعّلاً** حتى في نسخة الويب.

## 7. نسخة سطح المكتب (Windows / Linux)

### تجربة سريعة على جهازك

```bash
npm run electron:start        # يبني الواجهة ثم يفتح التطبيق
```

### بناء ملف تثبيت واحد لويندوز (المُوصى به)

```bash
npm run make:setup
```

ينتج **ملفاً واحداً** يُرسل للعميل:

```
electron-release/ERP-Setup-1.0.2.exe     ≈ 95 ميغابايت
```

عند تشغيله على ويندوز يقوم بما يقوم به أي برنامج تجاري:

- يثبّت في `C:\Program Files\ERP`
- ينشئ اختصاراً على **سطح المكتب** وفي **قائمة ابدأ**
- يسجّل البرنامج في **«التطبيقات والميزات»** مع أداة إزالة كاملة
- واجهة التثبيت **بالعربية**، والإزالة **لا تحذف بياناتك** (`%APPDATA%\erp`)

يحتاج جهاز البناء إلى NSIS: `apt-get install nsis` (أو تثبيت NSIS على ويندوز).

### التحديث التلقائي (auto-update)

النسخة المثبّتة تحدّث نفسها من **GitHub Releases**: تتحقق بعد 20 ثانية من
الإقلاع ثم كل 4 ساعات، تنزّل الإصدار الجديد في الخلفية، ثم تطلب من المستخدم
**إعادة التشغيل** فقط — لا تنزيل يدوي ولا إعادة تثبيت.

لنشر إصدار جديد للعملاء:

```bash
# 1) ارفع الرقم في package.json  (مثلاً 1.0.2 → 1.0.3)
npm run make:setup           # 2) بناء المثبِّت الجديد
npm run release:publish      # 3) إنشاء الوسم v1.0.3 ورفع المثبِّت + latest.yml
```

الخطوة الثالثة ترفع ملفين: المثبِّت نفسه، و`latest.yml` الذي يقرأه البرنامج
ليعرف أن هناك إصداراً أحدث ويتحقق من بصمة الملف قبل تثبيته. **الوسم لا بد أن
يكون `v<version>` بالضبط**، وإلا تجاهله المحدِّث.

عند العميل: صندوق «تحديث جاهز» عند اكتمال التنزيل، وبطاقة **«تحديثات البرنامج»**
في الإعدادات (الإصدار الحالي، نسبة التنزيل، زر «التحقق الآن»، وخيار إيقاف
التحديث التلقائي)، و«مساعدة ← التحقق من وجود تحديث…» في القائمة العلوية.
التثبيت يطلب موافقة UAC مرة واحدة، والبيانات في `%APPDATA%\erp` لا تتأثر.

التفاصيل الكاملة في [`electron/README.md`](electron/README.md).

### بناء مجلد البرنامج فقط (بلا مثبِّت)

```bash
npm run make:win
```

النتيجة في `electron-release/ERP-win32-x64/ERP.exe` — انسخ **المجلد كاملاً**
(وليس ملف الـ `exe` وحده) إلى جهاز الويندوز وشغّل `ERP.exe`.

> الحجم ≈ 350 ميغابايت لأن Electron يحمل متصفح Chromium كاملاً — هذا طبيعي.
> المثبِّت يضغطه إلى ≈ 95 ميغابايت.

### ماذا يحتاج جهاز البناء؟

| الحالة                          | النتيجة                                                            |
| ------------------------------- | ------------------------------------------------------------------ |
| البناء على ويندوز               | كل شيء يعمل مباشرة                                                 |
| البناء على لينكس مع `wine` مثبت | كل شيء يعمل، بما فيه الأيقونة وبيانات الإصدار                      |
| البناء على لينكس بلا `wine`     | الـ exe يعمل لكن بأيقونة Electron الافتراضية وبلا بيانات إصدار     |
| بلا `nsis`                      | `make:win` يعمل، و`make:installer` يتوقف برسالة تشرح كيفية التثبيت |

### لماذا لا يبدو كموقع ويب؟

نسخة سطح المكتب ليست الموقع داخل نافذة — أُزيلت منها كل ملامح المتصفح:

| الملمح                           | ماذا يحدث في البرنامج                                |
| -------------------------------- | ---------------------------------------------------- |
| شاشة بيضاء عند الإقلاع           | شاشة بدء (splash) بشعار البرنامج                     |
| شريط عنوان / تحديث الصفحة        | لا وجود لهما — `F5` و`Ctrl+R` معطّلان                |
| قوائم المتصفح بالزر الأيمن       | قائمة عربية أصلية (قص/نسخ/لصق)                       |
| صناديق `confirm` الخاصة بالمتصفح | صناديق رسائل ويندوز أصلية بأزرار عربية               |
| تحديد أي نص بالماوس              | التحديد في الحقول والجداول فقط، كما في أي برنامج     |
| فتح رابط داخل النافذة            | يُفتح في متصفح النظام، والنافذة تبقى على البرنامج    |
| نسخة ثانية عند كل نقر            | نسخة واحدة فقط — النقر الثاني يُظهر النافذة المفتوحة |
| نافذة تبدأ بحجم ثابت             | تفتح بنفس الحجم والموضع اللذين تركتها عليهما         |
| شريط قوائم غائب                  | شريط قوائم عربي: ملف · تحرير · عرض · مساعدة          |

### بناء نسخة لينكس

```bash
npm run make:linux
```

### أين تُحفظ بيانات نسخة سطح المكتب؟

ملف `erp.db` يوضع في:

| النظام  | المسار                                     |
| ------- | ------------------------------------------ |
| Windows | `%APPDATA%\ERP\erp.db`                     |
| macOS   | `~/Library/Application Support/ERP/erp.db` |
| Linux   | `~/.config/ERP/erp.db`                     |

زر **«نسخة احتياطية»** في قائمة **«ملف»** يحفظ نسخة من هذا الملف في أي مكان.

## 8. النشر على سيرفر

البنية المعتمدة على fikradigital.online:

```
المتصفح ──HTTPS──► nginx ──proxy──► localhost:8080 ──► pm2 «erp» ──► .output/server/index.mjs
```

### النشر بأمر واحد (بعد الإعداد الأولي)

```bash
./scripts/deploy.sh
```

يقوم بـ: **البناء** ← **إعادة تشغيل pm2** ← **التأكد أن الموقع يرد 200** قبل أن يعلن النجاح.
إن فشل، يعرض آخر 30 سطراً من سجلات pm2.

### الإعداد الأولي للسيرفر (مرة واحدة)

**1) تشغيل التطبيق تحت pm2:**

```bash
cd /root/arabs-clone-magic
npm install && npm run build
PORT=8080 HOST=0.0.0.0 pm2 start .output/server/index.mjs --name erp
pm2 save && pm2 startup     # ليعود تلقائياً بعد إعادة تشغيل السيرفر
```

**2) إعداد nginx** — الملف `/etc/nginx/sites-available/erp`:

```nginx
server {
    server_name fikradigital.online www.fikradigital.online;
    location / {
        proxy_pass http://localhost:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
    listen 443 ssl;
    ssl_certificate     /etc/letsencrypt/live/fikradigital.online/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/fikradigital.online/privkey.pem;
}
```

**3) تفعيله وإصدار شهادة SSL:**

```bash
ln -s /etc/nginx/sites-available/erp /etc/nginx/sites-enabled/
nginx -t && systemctl reload nginx
certbot --nginx -d fikradigital.online -d www.fikradigital.online
```

### أوامر المتابعة

| الأمر             | الوظيفة                 |
| ----------------- | ----------------------- |
| `pm2 list`        | حالة التطبيق            |
| `pm2 logs erp`    | السجلات المباشرة        |
| `pm2 restart erp` | إعادة تشغيل             |
| `pm2 monit`       | مراقبة الذاكرة والمعالج |

> ⚠️ **لا تشغّل التطبيق يدوياً** بـ `node` أو `nohup` بينما pm2 يشغّله — النسختان تتصارعان على المنفذ 8080.

## 9. ترتيب العمل الصحيح

شاشة أمر الشراء مرقّمة بخطوات ①→⑥، اتبعها بالترتيب:

```
① المورد → ② بيانات الفاتورة → ③ البنود → ④ المصروفات → ⑤ التكلفة → ⑥ التسعير
```

| #   | الشاشة                          | ماذا تفعل                                                            |
| --- | ------------------------------- | -------------------------------------------------------------------- |
| 1   | الموردون                        | سجّل المورد (الاسم، الدولة، العملة)                                  |
| 2   | الإعدادات ← أسعار الصرف         | تأكد من أسعار العملات المستخدمة                                      |
| 3   | الإعدادات ← التسعيرات           | عرّف وجهات البيع ونسبها                                              |
| 4   | أمر الشراء ①                    | اختر المورد                                                          |
| 5   | أمر الشراء ②                    | رقم الفاتورة، التاريخ، العملة، سعر الصرف، رقم الحاوية، طريقة التوزيع |
| 6   | أمر الشراء ③                    | أدخل الأصناف (يدوياً · استيراد Excel · بحث من الكتالوج)              |
| 7   | أمر الشراء ④                    | أدخل المصاريف (شحن، جمارك، نقل…) بأي عملة                            |
| 8   | أمر الشراء ⑤                    | راجع التكلفة النهائية وسعر CBM                                       |
| 9   | التسعيرات (`F6`)                | راجع أسعار البيع لكل وجهة، بأي عملة، مع الطباعة والتصدير             |
| 10  | حفظ (`Ctrl+S`) ثم اعتماد (`F9`) | الاعتماد يجمّد الفاتورة ويحدّث تكلفة الأصناف في الكتالوج             |

> **مهم:** الأصناف تُضاف إلى **دليل الأصناف** تلقائياً عند **الحفظ**،
> و**آخر تكلفة** تتحدّث فقط عند **الاعتماد**.

📐 كل المعادلات المعتمدة مشروحة بأمثلة رقمية في **[docs/الدليل-الكامل.md](docs/الدليل-الكامل.md#7-المعادلات-المعتمدة)**.

## 14. حل المشاكل

| المشكلة                                | السبب                           | الحل                                                                             |
| -------------------------------------- | ------------------------------- | -------------------------------------------------------------------------------- |
| التعديلات لا تظهر على الموقع           | النسخة المنشورة قديمة           | `./scripts/deploy.sh` ثم `Ctrl+Shift+R`                                          |
| الموقع لا يفتح                         | التطبيق متوقف                   | `pm2 list` ثم `pm2 restart erp` · وراجع `pm2 logs erp`                           |
| «لا يوجد CBM مُدخل»                    | كل الأصناف بلا CBM              | أدخل CBM الطرد — أو استخدم التوزيع المئوي                                        |
| «التوزيع لا يساوي المصاريف»            | نسبة مصاريف مكتوبة يدوياً       | اضغط زر ↻ بجانب نسبة المصاريف لإعادة الحساب                                      |
| «العملة غير معرّفة»                    | العملة غير موجودة في جدول الصرف | أضِفها من الإعدادات ← أسعار الصرف                                                |
| البيانات اختفت                         | مسح بيانات المتصفح / متصفح آخر  | استعادة من السحابة (الإعدادات)                                                   |
| تعارض على المنفذ 8080                  | نسختان تعملان معاً              | أوقف اليدوية وأبقِ pm2 وحده                                                      |
| فشل `npm install` على `better-sqlite3` | أدوات البناء ناقصة              | ثبّت `build-essential` و `python3` — أو استخدم `npm run sqlite:prebuild` لويندوز |
| الـ EXE يظهر بأيقونة Electron          | `wine` غير مثبت على جهاز البناء | `apt-get install wine64` ثم أعد `npm run make:win`                               |

│   └── api/public/license/     خدمات الترخيص والنسخ الاحتياطي
├── lib/
│   ├── erp-store.ts            ★ محرّك الحساب (computePO) والتخزين
│   ├── erp-types.ts            أنواع البيانات
│   ├── local-db.ts             طبقة التخزين (متصفح / Electron)
│   ├── auth.ts                 الحسابات والصلاحيات
│   └── cloud-sync.ts           النسخ الاحتياطي السحابي
├── components/erp/             مكوّنات الواجهة (الجداول، الحقول، النوافذ)
└── integrations/supabase/      عميل Supabase (متصفح / خادم)

electron/                       نسخة سطح المكتب وقشرة الترخيص
electron-app/                   نقطة دخول واجهة Electron والخطوط المحلية
scripts/
├── deploy.sh                   النشر بأمر واحد
├── make-win.mjs                تحزيم ويندوز/لينكس
