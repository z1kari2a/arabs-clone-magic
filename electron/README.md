# ERP Desktop (Electron)

هذه ملفات تحويل النظام إلى برنامج ويندوز محلي مستقل.

## ملف التثبيت (المُخرَج النهائي للعميل)

```bash
npm run make:setup      # = make:win ثم make:installer
```

النتيجة ملف واحد:

```
electron-release/ERP-Setup-1.0.2.exe     ≈ 95 ميغابايت
```

يحتاج **NSIS** على جهاز البناء: `apt-get install nsis`.

ما يفعله المثبِّت على جهاز العميل:

| | |
|---|---|
| مكان التثبيت | `C:\Program Files\ERP` (يطلب صلاحية المدير مرة واحدة) |
| الاختصارات | سطح المكتب + قائمة ابدأ |
| سجل ويندوز | مُدرج في «التطبيقات والميزات» مع أداة إزالة |
| اللغة | واجهة التثبيت بالعربية |
| عند الإزالة | يُحذف البرنامج فقط — البيانات في `%APPDATA%\erp` تبقى |
| نسخة قيد التشغيل | تُغلق تلقائياً قبل التحديث (`taskkill`) |
| تثبيت صامت | `ERP-Setup-1.0.2.exe /S` — مفيد للتوزيع على عدة أجهزة |
| تشغيل بعد التثبيت الصامت | `‎/S --force-run` — يستعمله التحديث التلقائي |

السكربت: `scripts/make-installer.mjs` + `scripts/installer.nsi`
(الملف الثاني محفوظ بترميز UTF-8 مع BOM، وهو شرط ليقرأ `makensis` النصوص
العربية بشكل صحيح — لا تحذف الـ BOM عند التعديل).

## التحديث التلقائي

البرنامج المثبّت يتابع إصداراته بنفسه عبر **GitHub Releases** باستخدام
`electron-updater`: يتحقق بعد 20 ثانية من الإقلاع ثم كل 4 ساعات، ينزّل الإصدار
الجديد في الخلفية، ويطلب من المستخدم **إعادة التشغيل** فقط.

### نشر إصدار جديد

```bash
# 1) ارفع الرقم في package.json  (1.0.2 → 1.0.3)
npm run make:setup           # 2) ابنِ المثبِّت الجديد
npm run release:check        # 3) اختياري: يكتب latest.yml بلا رفع
npm run release:publish      # 4) ينشئ الوسم v1.0.3 ويرفع الملفين
```

`npm run release:publish -- --no-upload` يفعل كل شيء محلياً (latest.yml + تحديث
`release/` وبصمته) دون النشر على GitHub — مفيد للمراجعة قبل الرفع.

يُرفع ملفان، وكلاهما ضروري:

| الملف | لماذا |
|---|---|
| `ERP-Setup-<version>.exe` | المثبِّت نفسه |
| `latest.yml` | ما يقرأه البرنامج: رقم الإصدار، اسم الملف، حجمه، وبصمة sha512 |

> **الوسم لا بد أن يكون `v<version>` بالضبط** (مثل `v1.0.3`). أي وسم آخر
> (`v1.0.0-oneclick` مثلاً) يقرأه المحدِّث كإصدار تجريبي فيتجاهله.
>
> ويجب أن يكون الإصدار الجديد هو **Latest** على GitHub — وهذا ما يفعله
> `release:publish` تلقائياً (`--latest`).

اسم المستودع الذي يُجلب منه التحديث مكتوب في مكان واحد: ثابت `UPDATE_CONFIG` في
`scripts/make-win.mjs`، الذي يكتب `resources/app-update.yml` داخل الحزمة.
`electron-updater` يقرأ هذا الملف حتى لو ضُبط العنوان بالكود، لأن مجلد التنزيل
المؤقت (`updaterCacheDirName`) يُقرأ منه هو أيضاً.

### كيف يعمل عند العميل

| المرحلة | ما يحدث |
|---|---|
| التحقق | طلب واحد إلى GitHub؛ فشله (بلا إنترنت) صامت تماماً |
| التنزيل | في الخلفية، مع تحقق من بصمة sha512 قبل قبول الملف |
| الطلب | صندوق «تحديث جاهز» + بطاقة في «الإعدادات ← تحديثات البرنامج» |
| التثبيت | يُشغَّل المثبِّت بصلاحية مدير (UAC) بوسيطي `‎/S --force-run` |
| قبل الإغلاق | تُحفظ حالة النافذة وتُؤخذ نسخة احتياطية ثم تُغلق قاعدة البيانات |
| بعد التثبيت | يفتح البرنامج على الإصدار الجديد، والبيانات في `%APPDATA%\erp` كما هي |

يمكن للمستخدم إيقاف التحقق والتنزيل التلقائيين من بطاقة الإعدادات (يُحفظ الخيار
في `updater.json` بجانب بيانات المستخدم)، ويبقى زر «التحقق الآن» وقائمة
«مساعدة ← التحقق من وجود تحديث…» يعملان يدوياً.

**نقطتان في التنفيذ تستحقان الانتباه** (كلتاهما موثّقة في `electron/updater.cjs`):

1. `main.cjs` يحجب كل طلبات الشبكة، لكن الحجب على الجلسة الافتراضية بينما
   `electron-updater` يستعمل جلسة خاصة به — فالتحديث يمر والتطبيق يبقى محلياً.
2. `autoUpdater.quitAndInstall()` لا تُستعمل: هي تشغّل المثبِّت بطريقة لا تستطيع
   رفع نافذة UAC وتحتاج `elevate.exe` الذي يأتي مع electron-builder فقط. بدلاً
   منها يُشغَّل المثبِّت عبر `Start-Process -Verb RunAs`، ولا يُغلق البرنامج إلا
   بعد أن يوافق المستخدم على UAC فعلاً.

## مجلد البرنامج بلا مثبِّت

```bash
npm run make:win
```

أمر واحد يقوم بكل شيء: بناء الواجهة، جلب مكتبة SQLite الخاصة بويندوز، التحزيم،
ثم التحقق من أن الناتج كامل. النتيجة في:

```
electron-release/ERP-win32-x64/ERP.exe
```

انسخ **المجلد كاملاً** (وليس ملف الـ exe وحده) إلى جهاز الويندوز وشغّل `ERP.exe`.

الحجم ≈ 350 ميغابايت لأن Electron يحمل متصفح Chromium كاملاً — هذا طبيعي.

### ماذا يحتاج جهاز البناء؟

| الحالة | النتيجة |
|---|---|
| البناء على ويندوز | كل شيء يعمل مباشرة |
| البناء على لينكس مع `wine` مثبت | كل شيء يعمل، بما فيه الأيقونة وبيانات الإصدار |
| البناء على لينكس بلا `wine` | الـ exe يعمل لكن بأيقونة Electron الافتراضية وبلا بيانات إصدار |

على أوبونتو: `apt-get install wine64` (السكربت يجده تلقائياً حتى لو لم يكن في `PATH`).

## أوامر مساعدة

```bash
npm run build:electron   # بناء الواجهة فقط إلى dist-electron/
npm run electron:start   # بناء + تشغيل محلي للتجربة
npm run icon             # إعادة توليد build/icon.ico من public/favicon.ico
npm run fonts:fetch      # إعادة تحميل خط Cairo المحلي
npm run sqlite:prebuild  # جلب better_sqlite3.node لويندوز فقط
npm run make:linux       # نفس التحزيم لكن لهدف لينكس (للفحص)
```

`icon` و `fonts:fetch` تحتاجان إنترنت/مكتبة sharp، ونواتجهما **محفوظة في المستودع**،
فالبناء العادي لا يحتاج تشغيلهما.

## لماذا سكربت بدل `electron-packager` مباشرة؟

`package.json` يحتوي على منتجين يتشاركان نفس المستودع:

- `electron/main.cjs` — البرنامج المستقل (هذا المقصود بـ `make:win`)
- `electron/shell-main.cjs` — قشرة الترخيص التي تنزّل الحزمة من السيرفر

حقل `main` يشير إلى الثاني، لذلك `electron-packager` وحده كان ينتج برنامج القشرة
بالخطأ. `scripts/make-win.mjs` يصحح ذلك داخل الحزمة، ويحقن نسخة SQLite الخاصة
بويندوز (وحدة native لا يمكن بناؤها على لينكس)، ويستبعد شجرة React من
`node_modules` لأنها مدمجة أصلاً في `dist-electron`.

## أين تُحفظ البيانات؟

ملف `erp.db` يوضع في:

- Windows: `%APPDATA%\ERP\erp.db`
- macOS:   `~/Library/Application Support/ERP/erp.db`
- Linux:   `~/.config/ERP/erp.db`

زر "نسخة احتياطية" في قائمة "ملف" يتيح لك حفظ نسخة من هذا الملف في أي مكان.

## ما الذي يجعله «برنامجاً» لا صفحة ويب؟

الفارق ليس في النافذة وحدها — كل سلوك يشي بالمتصفح أُزيل صراحةً:

| الملف | ما يفعله |
|---|---|
| `electron/main.cjs` | نسخة واحدة فقط (`requestSingleInstanceLock`)، حفظ حجم/موضع النافذة في `window-state.json`، قائمة عربية أصلية، منع التنقّل خارج التطبيق، تحويل الروابط إلى متصفح النظام، منع `F5`/`Ctrl+R`/`Ctrl+W`/رجوع-وتقدّم، قائمة زر الفأرة اليمنى الأصلية، تأكيد الإغلاق، معالجة الانهيار وعدم الاستجابة |
| `electron/splash.html` | شاشة بدء تُعرض أثناء إقلاع الواجهة بدل الإطار الأبيض |
| `electron/preload.cjs` | جسر آمن للبيانات + إبطال السحب والإفلات + `confirmSync`/`alertSync` |
| `electron-app/desktop.css` | إلغاء تحديد النص خارج الحقول والجداول، مؤشر الفأرة الافتراضي، منع سحب الصور، أشرطة تمرير هادئة، أنماط الطباعة |
| `electron-app/entry.tsx` | استبدال `window.confirm`/`window.alert` بصناديق رسائل ويندوز أصلية |

هذه الملفات كلها خاصة بنسخة سطح المكتب — نسخة الويب لا تتأثر بأي منها.

## يعمل بلا إنترنت

الخط (Cairo) مضمَّن محلياً، ولا توجد أي طلبات شبكة عند الإقلاع — تم التحقق من
ذلك عبر `performance.getEntriesByType('resource')` على الحزمة المبنية.

الاستثناء الوحيد هو **التحقق من التحديثات**: طلب واحد إلى GitHub من العملية
الرئيسية (لا من الواجهة)، بعد 20 ثانية من الإقلاع، وفشله بلا إنترنت لا يظهر
للمستخدم ولا يؤخر أي شيء. يمكن إيقافه كلياً من بطاقة الإعدادات.
