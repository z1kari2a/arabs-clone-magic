# نظام تراخيص + تفعيل + تشفير — دمج (2 + 3 + 4)

## البنية النهائية

```text
┌──────────────────────────────────────────┐
│  خادم التراخيص (Supabase)           │
│  - جدول licenses (رموز، نوع، صلاحية)    │
│  - جدول activations (جهاز مرتبط)         │
│  - جدول app_bundles (الكود المشفّر)      │
│  - جدول heartbeats (آخر اتصال)           │
│  - لوحة إدارة (لك أنت فقط)              │
└──────────────┬───────────────────────────┘
               │ HTTPS + توقيع RSA
┌──────────────▼───────────────────────────┐
│  Shell صغير على جهاز العميل (~25MB)     │
│  ┌────────────────────────────────────┐  │
│  │  1. شاشة إدخال رمز التفعيل         │  │
│  │  2. توليد Machine Fingerprint      │  │
│  │  3. طلب تفعيل من الخادم            │  │
│  │  4. تنزيل bundle مشفّر             │  │
│  │  5. فك التشفير في الذاكرة فقط      │  │
│  │  6. تشغيل النظام                   │  │
│  └────────────────────────────────────┘  │
└──────────────────────────────────────────┘
```

## 1) خادم التراخيص (Supabase)

**الجداول:**

- `licenses`: `code` (فريد), `type` (`permanent` | `monthly`), `expires_at`, `max_devices` (افتراضي 1), `active`, `notes` (اسم العميل).
- `activations`: `license_id`, `machine_fingerprint` (hash من CPU+MAC+Disk), `activated_at`, `last_seen_at`, `device_name`.
- `app_bundles`: `version`, `encrypted_blob` (الكود الفعلي المشفّر بـ AES-256), `signature` (توقيع RSA), `min_shell_version`.
- `heartbeats`: سجل كل اتصال (للمراقبة والكشف عن الاستخدام المتزامن).

**RLS:** لا أحد يقرأ مباشرة — كل شيء عبر server functions.

## 2) لوحة إدارة (لك فقط)

صفحة `/admin/licenses` محمية بـ role=`admin`:

- إنشاء رمز جديد (اختر: دائم / شهري / عدد الأجهزة / اسم العميل).
- عرض كل الرموز + حالة كل جهاز + آخر اتصال.
- تعطيل/تفعيل رمز فوراً (كل الأجهزة تتوقف خلال دقائق).
- تمديد صلاحية رمز شهري.
- عرض bundle الحالي ورفع نسخة جديدة (كل الأجهزة تحدّث تلقائياً).

## 3) Server Functions (نقاط الاتصال)

- `POST /api/public/license/activate` — جسم: `{ code, fingerprint, device_name }` → يعيد `{ session_token, bundle_url, decrypt_key_encrypted }`. يرفض إن: الرمز غير موجود / منتهي / وصل حد الأجهزة / معطّل.
- `POST /api/public/license/heartbeat` — جسم: `{ session_token, fingerprint }` → يعيد `{ valid: true, expires_at }`. يُستدعى كل 30 دقيقة. فشله 3 مرات = قفل البرنامج.
- `GET /api/public/bundle/:version` — يعيد الـ blob المشفّر (يتطلب `session_token` صالح في الهيدر).
- `POST /api/public/license/deactivate` — لتحرير الجهاز إذا احتاج العميل نقله لجهاز آخر.

## 4) Shell (البرنامج المُرسَل للعميل)

**Electron صغير جداً** — لا يحتوي على أي منطق ERP:

- شاشة تفعيل بسيطة (رمز التفعيل + اسم الجهاز).
- توليد fingerprint: `SHA256(cpuInfo + primaryMac + diskSerial)`.
- عند التفعيل الأول: يخزّن `session_token` في `%APPDATA%/erp-license.dat` (مشفّر بمفتاح مشتق من fingerprint).
- ينزّل bundle مشفّر → يفكّه في الذاكرة → يحقن الكود في نافذة Electron.
- الملفات على القرص = binary مشفّر لا يعمل بدون الخادم.

## 5) التشفير

- **Bundle**: `AES-256-GCM`. المفتاح يُشتق من `session_token` (KDF).
- **التوقيع**: كل bundle موقّع بـ `RSA-4096` — الـ shell يتحقق قبل التنفيذ (يمنع حقن bundle مزيّف).
- **Obfuscation**: قبل التشفير، الكود يمر عبر `javascript-obfuscator` (control flow flattening + string encryption).
- **مفتاح RSA الخاص**: محفوظ في Supabase secrets، يوقّع تلقائياً عند رفع bundle جديد.

## 6) الحماية ضد الكسر

| التهديد                            | الحماية                                      |
| ---------------------------------- | -------------------------------------------- |
| نسخ الملفات لجهاز آخر              | fingerprint مختلف → الخادم يرفض              |
| تعطيل الإنترنت للأبد               | فقدان heartbeat 3 مرات = قفل                 |
| فتح الملف بمحرر نصوص               | AES-256، بدون مفتاح = عشوائي                 |
| Reverse engineering للـ shell      | Obfuscation + الكود الأساسي ليس في الـ shell |
| مشاركة رمز التفعيل                 | `max_devices=1` → الجهاز الثاني يُرفض        |
| تعديل نظام التاريخ لتجاوز الاشتراك | الخادم يتحقق من التاريخ، لا الجهاز           |

## 7) تجربة العميل

1. تحمّل `MyERP-Setup.exe` (~25MB) من رابطك.
2. تثبيت → شاشة تفعيل تظهر.
3. يدخل الرمز الذي أرسلته له.
4. تنزيل ~15MB (الكود الفعلي) — يظهر شريط تقدم.
5. البرنامج يبدأ العمل — لن يطلب الرمز مرة أخرى على نفس الجهاز.
6. إذا انتهى الاشتراك الشهري: يظهر تنبيه قبل 7 أيام، ثم يُقفل.

## 8) ما ستراه أنت (المطوّر)

لوحة إدارة تعرض:

- كل عميل: اسم + نوع الاشتراك + تاريخ الانتهاء + الجهاز + آخر اتصال.
- زر «إلغاء التفعيل» فوراً.
- زر «تمديد» للاشتراكات الشهرية.
- زر «رفع تحديث جديد» — كل الأجهزة تحدّث خلال ساعة تلقائياً.

## 9) خطوات التنفيذ (بالترتيب)

1. **Supabase**: إنشاء الجداول + RLS + توليد مفتاح RSA + تخزينه في secrets.
2. **Server functions**: activate / heartbeat / bundle / deactivate + توقيع.
3. **لوحة الإدارة**: `/admin/licenses` (للمطوّر فقط).
4. **بناء الـ Bundle**: script يأخذ `dist/` الحالي → obfuscate → AES encrypt → يرفعه للجدول.
5. **Shell جديد**: مشروع Electron منفصل بسيط جداً + شاشة تفعيل + منطق التنزيل.
6. **اختبار end-to-end**: رمز → تفعيل → تنزيل → تشغيل → heartbeat → إلغاء.
7. **بناء `.exe`** جاهز للإرسال.

## 10) ما يتغيّر في تجربتك الحالية

- **البرنامج الحالي** يبقى كما هو (نفس الشاشات، نفس الحسابات) — هو ما سيصير الـ bundle المشفّر.
- **الفرق الوحيد**: عند البناء، يمر بمرحلة obfuscation + encryption قبل الرفع.
- **لك أنت**: تدخل لوحة الإدارة، تولّد رمز، ترسله للعميل — انتهى.

## 11) تحذيرات ضرورية

- **الحماية 100% مستحيلة** — أي برنامج يعمل محلياً يمكن نظرياً كسره بجهد كبير. هذا النظام يجعل الجهد أكبر من قيمة البرنامج لأي شخص عادي.
- **إذا انقطع خادمك** = كل النسخ تتوقف. سنضيف مهلة سماح (grace period) 7 أيام offline قبل القفل.
- **تكلفة خادم التراخيص**: مجاني على Supabase للاستخدام العادي.
